# CLAUDE.md

Guidance for Claude Code working in this repository.

## Project

Home Assistant custom integration (domain `cherkasy_outage`) for Cherkasyoblenergo power
outages for one personal account (особовий рахунок). Cloud polling, no extra PyPI
requirements (aiohttp/voluptuous/certifi come with HA). Installed via HACS custom repo.

## Data sources (verified live 2026-10-06)

- **News API**: `GET https://www.cherkasyoblenergo.com/api/v1/posts/category/news?lang=uk&page=0&size=20`,
  then `GET /api/v1/posts/{slug}?lang=uk` → `data.content` (HTML). Schedule posts are titled
  "Графік погодинних відключень (ГПВ) на 7 жовтня"; corrections "Оновлено графік … на 6 жовтня".
  The latest published post per date wins. The HTML splits times across `<span>`s, so always
  strip tags first (`parser.html_to_text`). `publishedAt` is naive Kyiv time. "24:00" means
  the next midnight.
- **Cabinet API**: `GET https://cabinet.cherkasyoblenergo.com/api_new/disconn.php?op=…`. Responses
  are JSON labelled `application/x-javascript`. Collections may be arrays or index-keyed objects
  (`parser.as_list`).
  - `disconn_by_ls&abon_ls=&disconn_selector=0|1|2&n_date=DD.MM.YYYY&k_date=`: 0 = planned,
    1 = emergency, 2 = only `DISCONN_QUEUQ` (sic) queue strings for the account. Selector 2 does
    **not** return ГПВ windows for Cherkasy city.
  - Record fields: `DISCONN_TYPE`, `DATE_START` "HH:MM DD.MM.YYYY", `DATE_STOP` (may end
    " (план)"), `STATE_INT` ("0" planned/expected, "-1" finished), `STATE_CHAR`, `ADDRESS`
    (HTML), optional `DATE_TIME` (HTML). No id field.
  - An unknown account gets the same empty shape; selector 2 gives an empty `DISCONN_QUEUQ`.
  - `DATETIME` looked one hour behind Kyiv time. Don't rely on its time zone.
  - Address ops: `department_list`, `city_list&dept_id`, `street_list&city_id&search_name`,
    `house_list&street_id&search_name=`, `ls_list_by_addr&street_id&house`.
  - **TLS**: the host sends no intermediate certificate. `api.SECTIGO_DV_R36_PEM` is added to a
    certifi-based context (built in an executor, cached in `hass.data`) and used only for this host.

## Layout (`custom_components/cherkasy_outage/`)

- `const.py`, `models.py` (dataclasses), `parser.py` (pure functions, no HA imports).
- `api.py`: `OblenergoClient`, errors, `create_ssl_context`. No HA imports.
- `helpers.py`: `async_get_client(hass)`, `kyiv_tz()`.
- `coordinator.py`:
  - `ScheduleCoordinator` (news, every 10 min) and `AccountCoordinator` (cabinet, every 30 min),
    both `_TolerantCoordinator`s that serve the last data for up to 3 failures.
  - `OutageRuntime` (`entry.runtime_data`) merges both into `outages`. It fires
    `cherkasy_outage_schedule_changed`, manages the Repairs issue for unreadable posts, and
    schedules a timer at the next window start or end so states flip on time.
- Platforms: `calendar.py`, `binary_sensor.py`, `sensor.py`. All entities share `entity.OutageEntity`.
  - They listen to the runtime, not to the coordinators directly.
  - Device `translation_key="outages"` gives the "Power outages" name, so entity IDs look like
    `sensor.power_outages_next_start`.
- `config_flow.py`: menu → by address (department → city → street search → street → house → account)
  or by account number. The queue is detected via selector 2; the `queue` step appears when none
  is reported. Options: `queue_override` (`auto` or e.g. `4.1`). `OptionsFlowWithReload`.
- `diagnostics.py`: redacts the account and address.
- `brand/icon.png`: generated by `make_icon.py`.

## Commands

```bash
pytest                                   # tests/: pure unit tests, HA not installed (conftest
                                         # registers the package without running __init__)
.venv-ha/bin/pytest tests_ha             # real HA core via pytest-homeassistant-custom-component
ruff check . && ruff format --check .
```

- Fixtures in `tests/fixtures` are real responses from 2026-10-06, with account numbers and
  address anonymised. Keep it that way: never commit a real account number.
- Keep the `requirements_test_ha.txt` pin in step with the HA version in use.
- Versioning: pushing to `main` triggers `release.yml`, which bumps the patch version in
  `manifest.json`, tags it and releases. Don't bump the version by hand except for a minor or
  major change.
